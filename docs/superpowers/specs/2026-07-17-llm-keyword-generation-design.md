# LLM 检索关键词生成设计

## 目标

根据用户画像生成与用户兴趣直接相关、同时更有机会召回热门内容的检索关键词。关键词不要求原样出现在画像字段中，但必须能够从用户原始数据解释出明确的语义联系。

相关性是硬约束；热度只用于相关候选之间的选择和排序，不能用热度替代相关性。

## 输入边界

LLM 只能以以下用户原始数据作为语义出发点：

- `level1`
- `level2`
- `personal.role`
- `personal.subject`
- `personal.scenarios`
- `personal.value`
- `core_keywords`

允许基于这些字段生成未在原文中出现的上位词、下位词、关联实体、知名人物、品牌、产品和常见热点表达。禁止生成无法说明其与任一输入字段存在直接联系的泛热点词。

## 关键词约束

- 去重后返回 3–10 个关键词。
- 中文概念优先压缩为 2–3 个字符的核心名词或实体词。
- 2–3 个字符是优先目标而非绝对限制；不可合理缩写的专有实体可以保留原名，例如 `OpenAI`、`DeepSeek`。
- 禁止句子、问题描述、堆叠修饰语，以及“新闻”“热点”“今日”“最新”等无独立主题含义的泛词。
- 同义词只在能够覆盖不同搜索表达时共存，避免仅为凑数量生成近义重复项。
- 有 3 个有效关键词即可成功，不为了凑满 10 个引入弱相关词。

## 分档规则

采用热榜优先的渐进分配：

| 总数 | 热榜 | 长尾 | 兜底 |
| ---: | ---: | ---: | ---: |
| 3 | 3 | 0 | 0 |
| 4 | 4 | 0 | 0 |
| 5 | 5 | 0 | 0 |
| 6 | 5 | 1 | 0 |
| 7 | 5 | 2 | 0 |
| 8 | 5 | 3 | 0 |
| 9 | 5 | 4 | 0 |
| 10 | 5 | 4 | 1 |

分档语义：

- `热榜`：与画像相关且覆盖面较广、近期讨论度或搜索召回潜力较高。
- `长尾`：相关性更精准，但受众或单次召回量较小。
- `兜底`：与画像直接相关的小众词，用于前两档召回不足时补充搜索。

## 提示词设计

系统提示词按以下优先级表达要求：

1. 先判断候选词能否从用户画像解释出直接联系。
2. 在相关候选中优先选择更可能带来热门内容的词。
3. 优先把中文概念压缩为 2–3 个字符，但保留不可合理缩写的专有实体。
4. 返回 3–10 个，不得为了达到上限牺牲相关性。
5. 按实际数量应用热榜优先的分档规则。
6. 严格输出当前下游兼容的 JSON 数组，不增加输出字段或解释文本。

用户提示词明确列出全部输入字段，并将原来的“生成 5–10 个”改成“生成 3–10 个”。提示词中的长度示例必须与实际字符数一致，不再把三字符词描述为两字符词。

## 解析、校验与重试

- 保持现有 `keyword`、`match_expectation` JSON 契约。
- 解析阶段校验非空、合法分档和去重，但不做“必须是原文连续子串”的检查。
- 不用硬编码的 2–3 字过滤器删除专有实体；长度偏好由提示词承担。
- 有效关键词达到 3 个即接受，最多保留 10 个。
- 少于 3 个时才重试 LLM；重试提示应强调缺少有效关键词以及相关性、格式要求。
- LLM 不可用时沿用 `core_keywords` 降级，但执行去重并最多保留 10 个；不能保证至少 3 个时返回现有有效项，不虚构补齐。
- 缓存读取遵守同一解析契约，避免旧缓存因新的长度偏好被无条件判为无效。

## 测试设计

在 `tests/test_llm_keywords.py` 中先建立失败测试，覆盖：

- 3 个有效关键词时不重试并成功返回。
- 2 个有效关键词时触发重试。
- 3–5 个结果全部标记为热榜。
- 6–9 个结果先保留 5 个热榜，其余为长尾。
- 10 个结果严格为 5 个热榜、4 个长尾、1 个兜底。
- 相关但未原样出现在画像中的关键词可以通过解析。
- `OpenAI`、`DeepSeek` 等必要实体不会因长度被删除。
- 超过 10 个时稳定截断，重复关键词被去除。
- 提示词包含相关性优先、热度次优先、3–10 个及长度偏好要求。
- 旧缓存中的合理长实体仍能读取。

定向测试通过后运行完整 pytest 测试，确认没有破坏画像注册、缓存和 pipeline 下游契约。

## 非目标

- 不接入实时热搜数据来验证关键词热度。
- 不改变关键词 JSON 数据结构。
- 不修改搜索、排序、摘要或文章抓取流程。
- 不保证 LLM 对相关性和热度的判断绝对正确；本次通过清晰提示词、数量门槛和结构校验降低偏差。
